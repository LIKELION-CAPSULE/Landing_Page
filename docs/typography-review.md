# 모바일·데스크톱 글자 크기 점검

점검일: 2026-10-11 (한국 시간)

제목은 화면과 화면 폭에 따라 달라지고, 입력칸·동의·오류·약관 전문은 공통 크기를 사용한다. 투표와 사전예약의 제목·설명 크기는 일치하지만, 완료 화면의 설명과 버튼은 더 작다. 우선 개선할 부분은 모바일 랜딩의 작은 안내·약관 링크, 좁은 줄 간격, 같은 역할의 버튼·설명 크기 차이다.

이 문서는 측정 결과와 개선 제안이다. 이번 점검에서 서비스 CSS와 컴포넌트는 수정하지 않았다.

## 측정 범위와 방법

- 로컬 개발 서버의 현재 코드를 Chrome에서 렌더링했다. 320·390·402·767·768·1023·1024·1440·1920px의 9개 화면 폭을 확인했다. 모바일 높이는 844px, 태블릿·PC 높이는 900px이다.
- 랜딩 → 룸 투표 → 상세 → 투표 성공 → 사전예약 → 약관 요약·개인정보 전문 → 입력 오류 → 예약 완료 → 설문을 확인했다.
- 글꼴 로딩 후 브라우저가 계산한 `font-size`, `line-height`, 굵기, 요소 너비와 가로 넘침을 측정했다. 시연 내부는 부모의 축소 변환까지 계산해 표시 크기를 구분했다.
- 화면 비교에는 모션 줄이기를 사용했다. Supabase 저장·집계와 외부 분석 요청은 테스트 응답으로 대체했다. 실제 예약·투표·설문 데이터는 만들지 않았다.
- 휴대폰 실기기와 앱 내 브라우저의 글자 자동 보정은 이번 측정 범위에 포함하지 않았다. 포스터 그림에 인쇄된 글자는 CSS 글자 크기로 측정할 수 없어 아래 표에서 제외했다.
- 9개 폭 모두 측정 대상 주요 문구의 요소 내부 가로 넘침과 페이지 가로 스크롤이 없었고, 최종 측정의 JavaScript 오류도 없었다.

## 화면별 비교

대표 모바일은 **390px**, PC는 **1440px** 너비다. 단위는 CSS px이며 소수점 첫째 자리로 반올림했다. 본문은 각 화면의 제목 바로 아래 설명, 버튼은 주요 행동을 기준으로 한다.

| 화면 | 모바일 제목 | PC 제목 | 모바일 설명 | PC 설명 | 모바일 주요 버튼 | PC 주요 버튼 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| 랜딩 첫 화면 | 33.0 | 51.8 | 19.4 | 20 | 19.4¹ | 18¹ |
| 룸 투표 | 38.8 | 44 | 17.5 | 18 | 16.5² | 17² |
| 사전예약 | 38.8 | 44 | 17.5 | 18 | 19.4 | 20 |
| 예약 완료 | 31.0 | 38 | 15 | 15 | 16 | 16 |
| 설문 | 38.8 | 40 | 15.5 | 18 | 19.4 | 20 |

¹ 랜딩 하단의 “다른 스터디룸 구경하고 투표하기” 버튼. ² 룸 상세의 “이 스터디룸 투표하기” 버튼.

투표·예약·설문 제목은 모바일에서 같은 규칙(`max(2rem, 40 × --u)`)을 사용한다. 320px에서는 모두 32px, 402px 이상 모바일에서는 40px이다. PC에서는 투표·예약이 44px, 설문이 40px이다. 완료 제목은 모바일 28~32px, PC 38px으로 한 단계 작다. 랜딩 Hero는 모바일 27.1~34px, PC 38~54px으로 더 넓게 변한다.

랜딩은 소개 문구와 섹션 제목에 별도 위계를 사용한다. 이 차이는 화면의 역할과 배치에 맞는 선택이다. 모든 제목을 동일한 숫자로 맞추기보다 같은 역할의 설명과 버튼부터 정리하는 편이 좋다.

## 개선 우선순위

### 1. 모바일 안내와 약관 링크의 최소 크기

`src/styles.css`의 `.notice__body`, `.footer`, `.footer__links`, `.hero__preview figcaption`, `.scroll-hint`, `.step__desc`에 읽을 수 있는 하한을 둔다.

- STEP 설명은 모바일에서 **16px**을 목표로 한다.
- 출시·기기·카메라 안내, 이메일·인스타그램, 약관 링크는 **14px** 하한을 권장한다.
- 저작권과 출처처럼 부수적인 정보도 **11~12px** 정도로 읽을 수 있게 조정한다.

폰트만 키우면 기존 고정 높이·절대 위치·강제 줄바꿈에서 겹침이 생길 수 있다. 모바일 푸터의 줄 간격·위치·높이와 STEP 설명의 `white-space: nowrap`을 함께 조정해야 한다. 이 수치는 서비스의 가독성을 위한 디자인 제안이다.

### 2. 모바일 설명의 줄 간격

모바일 STEP 설명은 글자 16에 줄 높이 19로 약 **1.19배**, PC는 18에 줄 높이 30.6으로 **1.7배**다. 모바일 안내 본문도 약 **1.31배**로 PC의 1.8배보다 촘촘하다.

모바일 설명은 **1.5~1.6배**를 시작점으로 조정하고, 기존 `<br>`와 `nowrap`을 검토한다. 문구 길이에 맞춰 섹션 높이도 늘어나게 하는 것이 좋다. 이는 기본 디자인 권장값이며, WCAG의 텍스트 간격 기준은 사용자가 줄·글자·단어 간격을 변경했을 때 내용과 기능을 유지하는지에 관한 것이다. [W3C 텍스트 간격 안내](https://www.w3.org/WAI/WCAG21/Understanding/text-spacing)

### 3. 같은 역할의 설명과 버튼

“출시되면 이메일로 가장 먼저 알려드릴게요.”라는 같은 문장이 사전예약에서는 모바일 **17.5px**·PC **18px**, 완료에서는 양쪽 모두 **15px**이다. 같은 안내 역할이면 공통 설명 크기를 사용하는 것이 자연스럽다.

주요 버튼은 대표 모바일에서 랜딩·예약·설문 **19.4px**, 룸 상세 **16.5px**, 완료 **16px**이다. PC에서는 각각 **18 / 20 / 20 / 17 / 16px**이다.

서비스 전반에 **주요 버튼 18px**, **보조 버튼 16px**, **텍스트 동작 14px** 같은 역할별 규칙을 만들고 공유한다. 완료 화면의 “처음으로 돌아가기”처럼 보조 동작까지 주요 버튼과 같은 크기로 만들 필요는 없다. 설명은 모바일 16px·PC 18px을 공통 기준으로 검토한다.

### 4. 태블릿에서 PC로 넘어갈 때의 크기 변화

| 요소 | 1023px | 1024px |
| --- | ---: | ---: |
| 고민 제목 | 50 | 40 |
| STEP 제목 | 32 | 28 |
| 랜딩 투표 버튼 | 25 | 18 |

태블릿에서 `.problem`, `.rooms`가 `--u: 1.25px`을 사용하면서 글자까지 커지고, PC 레이아웃으로 전환할 때 명시적인 작은 값으로 바뀐다. 배치가 바뀌는 이유는 있지만 화면이 넓어지는 순간 글자는 줄어드는 변화가 눈에 띈다.

그림 크기를 조절하는 단위와 본문·버튼 글자 크기를 분리하고, 제목은 공통 `clamp()` 범위를 사용해 변화 폭을 줄이는 것이 좋다.

### 5. 시연 내부의 작은 글자

시연은 1480px 원본 UI를 축소해 표시한다. 모바일에서 일부 이름표·메뉴·설명은 표시 크기가 **3~8px**다. 페이지 본문이나 입력 UI와 역할이 다르므로 전체 화면의 폰트 규칙을 그대로 적용하면 시연 구도가 바뀐다.

기능 이해에 필요한 공부 시간·호감도·대사는 확대 장면과 시연 밖의 설명으로 읽을 수 있게 하고, 작은 메뉴는 장식으로 취급하는 방향이 적절하다. 숫자와 대사를 키우는 경우에도 장면별 카메라 확대를 함께 확인한다.

## 글자 확대 보조 확인

390px·1440px 설문에서 루트 글자 크기를 16px에서 32px로 바꿔 확인했다. 제목·입력·선택 항목은 `rem` 하한을 따라 커졌고 가로 넘침이 없었다. PC의 18px 설명처럼 고정 px 규칙은 이 설정에 따라 커지지 않았다. 이 확인은 브라우저 전체 페이지 200% 줌이나 모든 화면의 확대 검증을 대체하지 않는다.

향후 공통 글자 규칙은 `rem`을 중심으로 만들고, 수정 후 브라우저 확대와 줄 간격 변경도 확인한다. [W3C 글자 확대 안내](https://www.w3.org/WAI/WCAG21/Understanding/resize-text)

## 구현 위치

- `src/styles.css`: 모바일 기본 글자 크기, 화면별 제목·설명, 버튼·입력·동의·안내.
- `src/styles/responsive.css`: 768px·1024px 이상 제목과 본문·레이아웃 보정.
- `src/components/LegalDocumentDialog.css`: 전문 제목·본문·표.
- `src/components/StepDemo.css`, `src/components/RoomSelectPreview.css`, `src/hooks/useDemoCanvas.ts`: 시연 내부 글자와 전체 축소.

추천 작업 순서는 **모바일 글자 하한·줄 간격 → 공통 설명·버튼 → 태블릿 전환 보정**이다. 제목 크기 차이 자체보다 읽어야 할 안내의 가독성과 같은 역할의 일관성을 먼저 개선한다.
