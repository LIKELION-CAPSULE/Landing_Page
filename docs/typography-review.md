# 모바일·PC 글자 크기 개선 결과

점검·반영일: 2026-10-11 (한국 시간)

모바일과 PC 모두 수정했다. 읽는 글자와 버튼에 공통 `rem` 규칙을 적용했고, 그림 크기를 조절하는 `--u`가 주요 설명·안내·버튼까지 축소하지 않도록 분리했다. 제목은 화면의 역할과 배치에 따른 위계를 유지한다.

## 반영한 크기 규칙

기본 루트 글자 크기 16px에서의 값이다. PC 규칙은 태블릿을 포함한 **768px 이상**에 적용한다.

| 역할 | 모바일 | 태블릿·PC | 적용 대상 |
| --- | ---: | ---: | --- |
| 주요 설명 | 16px | 18px | STEP 설명, 투표·예약·완료·설문 설명, 투표 성공 안내 |
| 상세 안내 | 14px | 16px | 랜딩의 출시·기기·카메라·캐릭터 안내 |
| 보조 안내·링크 | 14px | 14px | 캡션, 스크롤 안내, 푸터 연락처·약관 링크, 예약 개인정보 안내 |
| 부수 표기 | 12px | 12px | 저작권, MacBook 출처 |
| 선택 항목 | 16px | 16px | 설문의 일반·compact 선택 버튼 |
| 주요 버튼 | 18px | 18px | 랜딩 투표, 룸 상세 투표, 예약 제출, 설문 제출, 완료 화면의 주요 동작 |

완료 화면의 “처음으로 돌아가기” 같은 텍스트 동작은 14px이다. 이메일·설문 입력 16px, 동의·오류 14px, 약관 전문 본문 16px은 기존 공통 크기를 유지한다. 랜딩 첫 화면의 소개 문구는 강조 문구로서 모바일 16~20px, PC 최대 20px을 사용한다.

`src/styles.css`의 `--font-body`, `--font-detail`, `--font-caption`, `--font-small`, `--font-control`, `--font-button`으로 규칙을 공유한다. `src/styles/responsive.css`에서는 주요 설명과 상세 안내 토큰만 각각 18px·16px으로 변경한다.

## 변경 전후

단위는 CSS px이며 소수점 첫째 자리로 반올림했다. 대표 모바일은 390px, PC는 1440px이다.

| 요소 | 모바일 변경 전 → 후 | PC 변경 전 → 후 |
| --- | ---: | ---: |
| 투표·사전예약 설명 | 17.5 → 16 | 18 → 18 |
| 완료 설명 | 15 → 16 | 15 → 18 |
| 설문 설명 | 15.5 → 16 | 18 → 18 |
| STEP 설명 | 15.5 → 16 | 18 → 18 |
| 랜딩 상세 안내 | 12.6 → 14 | 15 → 16 |
| 푸터 약관 링크 | 9.7 → 14 | 13 → 14 |
| 저작권 | 9.7 → 12 | 12 → 12 |
| MacBook 출처 | 6 → 12 | 9 → 12 |
| 랜딩 투표 버튼 | 19.4 → 18 | 18 → 18 |
| 룸 상세 투표 버튼 | 16.5 → 18 | 17 → 18 |
| 예약·설문 제출 버튼 | 19.4 → 18 | 20 → 18 |
| 완료 주요 버튼 | 16 → 18 | 16 → 18 |
| 예약 개인정보 안내 | 12 → 14 | 13 → 14 |

320px에서도 STEP 설명은 기존 12.7px에서 **16px**, 상세 안내는 10.3px에서 **14px**, 약관 링크는 8px에서 **14px**으로 개선했다. 화면마다 임의의 크기를 쓰던 설명·버튼은 공통 역할에 맞춰 정리했다.

## 줄 간격과 배치

- STEP 설명과 주요 화면 설명, 상세 안내의 줄 간격을 **1.6배**로 통일했다. 모바일 STEP 설명은 기존 약 1.19배에서 늘어났다.
- STEP 설명·제목의 강제 한 줄 표시를 제거하고, 좁은 화면에서는 자연스럽게 줄바꿈한다. 설명이 길어지면 시연 영역도 아래로 밀린다.
- 랜딩 상세 안내의 고정 `<br>`를 제거했다. 문장은 그대로 유지하며 화면 폭에 맞춰 줄바꿈한다.
- 모바일 푸터를 고정 높이·절대 위치에서 내용에 따라 높이가 늘어나는 배치로 바꿨다. 이메일은 좁은 폭에서 줄바꿈할 수 있고, 약관 버튼은 44px 이상 클릭 영역을 유지한다.
- 랜딩 갤러리는 버튼 아래 공간을 확보했다. 주요 버튼은 모바일에서도 최소 높이 48px을 유지한다.
- 출처 표기를 12px으로 키우고 명도를 높였다. 스크롤 안내와 출처 사이에 공간을 확보했고, 높이가 낮은 창에서는 스크롤 안내가 소개 캡션을 덮지 않도록 배치한다.
- 모션 줄이기 설정에서는 모바일도 첫 화면과 다음 섹션이 겹치지 않게 했다.

## 태블릿 → PC 전환

1023px과 1024px 경계에서 그림의 확대 단위가 달라져도 아래 글자는 갑자기 작아지지 않는다.

| 요소 | 변경 전 1023 → 1024px | 변경 후 1023 → 1024px |
| --- | ---: | ---: |
| 고민 제목 | 50 → 40px | 40 → 40px |
| STEP 제목 | 32 → 28px | 32 → 32px |
| 랜딩 투표 버튼 | 25 → 18px | 18 → 18px |

고민 제목은 태블릿·PC에서 공통 `clamp(2.5rem, 3.6vw, 3.125rem)`, STEP 제목은 `clamp(2rem, 2.5vw, 2.25rem)`을 사용한다. 1440px에서는 각각 50px·36px이다.

## 확인한 범위

- 로컬 Chrome에서 320·390·402·767·768·1023·1024·1440·1920px의 **9개 화면 폭**을 확인했다. 모바일 높이는 844px, 태블릿·PC 높이는 900px이다.
- 랜딩 → 룸 투표 → 상세 → 투표 성공 → 사전예약 → 약관 요약·개인정보 전문 → 입력 오류 → 완료 → 설문 흐름을 확인했다.
- 각 폭에서 주요 설명·안내·버튼의 계산된 크기에 대한 **15개 확인**, 총 135개가 통과했다. 측정 대상의 가로 넘침·페이지 가로 스크롤·처리되지 않은 JavaScript 예외(`pageerror`)는 없었다.
- 추가로 320×568·390×667 모바일, 768×600·1024×600 PC 창과 기본 모션·모션 줄이기 설정에서 첫 화면 안내·출처, STEP 본문·시연, 갤러리 버튼·안내의 겹침을 확인했다.
- 390px·1440px 설문에서 루트 글자 크기를 200%로 바꿨다. 공통 설명은 각각 32px·36px, 선택 항목은 32px으로 커지고 가로 넘침은 없었다. 이는 브라우저 전체 페이지 줌이나 모든 화면의 확대 검증을 대체하지 않는다.
- `npm run build`, `npm run lint`, `git diff --check`를 확인했다. 린트의 기존 MacBook 컴포넌트 경고와 빌드의 큰 번들 경고는 별도 항목이다.

검사 중 외부 저장·집계·분석 요청은 테스트 응답으로 대체했다. 실제 예약·투표·설문 데이터는 생성하지 않았다. 추가 배치 검사에서 분석 SDK가 테스트 응답에 대해 출력한 콘솔 메시지는 UI 예외와 구분했다. 운영 분석의 정상 동작, 휴대폰 실기기·카카오톡 내장 브라우저는 이번 검증 범위에 포함하지 않았다.

## 별도 위계를 유지한 부분

랜딩의 강조 제목, 투표·예약 제목, 완료 제목은 역할과 배치가 달라 모든 제목을 같은 크기로 맞추지 않았다. 포스터 그림에 인쇄된 글자와 1480px 원본을 축소한 시연 내부 글자도 페이지 본문 규칙과 구분한다. 이번 변경은 페이지에서 직접 읽고 조작하는 주요 설명·안내·버튼에 적용했다.

## iPhone 안내 문구 줄바꿈 후속 보정

실제 iPhone 화면에서 사전예약 하단의 “이메일은 출시 알림과…” 문단이 왼쪽에 몰려 보였다. Safari와 같은 WebKit에서 스크린샷과 동일한 줄바꿈을 재현했다. 402px 화면에서 문단과 입력칸의 폭은 모두 350px이지만, 기존 `text-wrap: pretty`가 각 글줄을 약 248~270px로 조정해 오른쪽에 큰 여백이 남았다. 14px으로 키운 글자가 기존 줄바꿈 설정과 만나 드러난 문제이며, 최초 점검은 Chrome 중심이어서 이 차이를 놓쳤다.

Safari의 `pretty`는 문단 전체 줄을 조정한다. [WebKit 설명](https://webkit.org/blog/16547/better-typography-with-text-wrap-pretty/)

이 문단에 `text-wrap: wrap`, `word-break: keep-all`, `overflow-wrap: anywhere`를 적용했다. 14px 크기와 입력칸에 맞춘 문단 폭을 유지하면서 공간을 채우고 어절 단위로 줄바꿈한다. 마지막 줄이 짧게 남는 것은 일반적인 문단 줄바꿈이다. 이 검증은 WebKit 시뮬레이션이며 iPhone 실기기 재확인은 별도다.

수정 후 WebKit·Chrome 각각 320·390·402·430·1440px에서 입력칸과 문단의 시작점·폭이 일치하고 가로 넘침이 없음을 확인했다. 두 엔진의 줄바꿈도 일치했다. 개인정보 전문 버튼과 이메일 입력 오류 동작, 프로덕션 빌드도 확인했다.

## 화면·브라우저 전수 검사 후속 보정

후속 검사에서는 19개 화면 크기 × Chromium·WebKit의 38개 기본 조합과 일반 모션·글꼴 실패·지연 조건을 확인했다. 글자 200% 확대에서 첫 화면 안내, 고민 섹션 제목, 갤러리 버튼, 선택 동의 팝업의 배치 문제를 고쳤다. PC 모션 줄이기의 섹션 겹침과 일반 모션에서 출처가 다음 제목 뒤에 비치는 전환도 보정했다.

자세한 범위·수치·한계와 수정 전후 스크린샷은 [기기 화면 크기·브라우저별 배치 검사](device-screen-review.md)에 기록했다. 위의 최초 9개 폭 검증보다 확대된 범위이며, 실제 기종의 실물 검증은 아니다.
