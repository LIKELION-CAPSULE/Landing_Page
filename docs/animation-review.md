# 애니메이션 점검 · 2026-10-10

이번 범위는 랜딩의 스크롤 모션, 세 STEP의 서비스 시연, `/rooms`의 포스터 확대 전환, 고민 섹션의 이미지·페이드 영역이다. React + CSS + Web Animations API를 사용하며 추가 라이브러리나 영상 파일을 설치하지 않았다. 후속 요청의 캡션 제거·장면 확대·알림 테두리 제거·포스터 하단 연결도 반영했다.

## 새 Figma 에셋 반영 · 2026-10-10

기존 줌·클릭 시연에 새 Figma 원본을 연결했다. STEP 1의 룸 선택은 그대로 사용하고, 입장 후 캠스터디는 STEP 2·3과 같은 기본 사진을 공유한다. STEP 2는 폰 확인 → 류다희의 지적하는 포즈 → 말 걸기 → 공부 복귀, STEP 3은 호감도 증가 → 세 캐릭터의 친밀감 포즈 → 에피소드로 이어진다.

### 사진·UI·재생 변경

- `StudySessionPreview.tsx`: 사진을 슬롯별로 배치하고 이름표·호감도 배지를 React UI로 구성한다. 이미지 속 말풍선 제거용 마스크와 전체 화면 좌표로 잘라 쓰던 캐릭터 크롭을 제거했다. 기본 사용자 사진의 소스 크롭은 Figma와 동일하게 유지한다.
- `StepDemo.css`: 포즈는 250ms `--ease-out` 불투명도 전환을 사용한다. STEP 2의 마지막 확대 대상은 아래쪽 류다희 카메라이며, 말풍선은 얼굴·가리키는 손 아래에 놓는다. STEP 3의 에피소드 알림도 아래로 옮겨 이어폰을 건네는 손을 보여준다. 설명용 줌 650ms `--ease-in-out`, 재생·정지 버튼과 알림의 테두리 없는 표현을 이어 사용한다.
- `useDemoPlayback.ts`: STEP 영역 300px 전부터 현재 사진을 준비하고, 화면에 들어오면 다음 장면을 미리 디코딩한다. 공통 기본 사진의 준비 결과를 공유한다. 다음 사진이 늦으면 이전 장면과 남은 시연 시간을 유지한다. 들어오는 사진을 먼저 불투명도 0으로 배치한 뒤 장면을 넘겨, 처음 불러오는 포즈도 페이드로 연결한다. 빠르게 여러 번 누르면 마지막으로 요청한 장면이 적용된다.
- 모션 줄이기에서는 확대·커서를 없애고 사진과 카드의 불투명도만 100ms로 바꾼다. 화면 밖·백그라운드 탭에서는 자동 진행을 멈춘다.

### 용량과 검증

선별한 9개는 합계 **13,228,622B (13.23MB)**다. 기본 사진 4개는 6.06MB, 반응 2개는 2.78MB, 친밀감 3개는 4.39MB다. 이전 합쳐진 WebP 두 개는 2.34MB였다. 선명도를 위해 원본 해상도를 유지했으며, 초기 랜딩 화면에서 모든 포즈를 요청하는 방식 대신 장면별 준비를 적용했다. 원본 자체는 정지 이미지다.

검증 결과:

- `npm run build`, `npm run lint`, `git diff --check` 통과.
- 독립된 Chrome 테스트 브라우저에서 320·402·1280px × STEP 3개 × 장면 5개, 총 45개 장면 확인. 모든 사진의 실제 원본 크기·읽을 대상의 화면 내 배치·44px 컨트롤·가로 스크롤 없음·알림 테두리 없음 확인. 320·402px의 최종 렌더에서 캐릭터 얼굴·가리키는 손·이어폰이 말풍선과 에피소드 알림에 가려지지 않는 것도 확인했다.
- STEP 3개 모두 자동 한 번 재생·일시정지·재재생·키보드 진행·화면 밖 정지·모션 줄이기 통과. 초기 랜딩 위치에서는 새 사진을 실제 이미지 요청으로 불러오지 않는 것을 확인했다.
- 기본·폰·반응 사진을 각각 지연시켜 이전 장면 유지·준비 후 진행 확인. 처음 불러온 반응 사진의 250ms 페이드 중 기본 사진이 계속 보임을 확인했다. 이미지 준비 중 백그라운드 탭 전환, 빠른 연속 클릭, 진행 중 모션 줄이기 변경, 화면 이동, IntersectionObserver 미지원 폴백도 확인했다. 브라우저 런타임 오류 0건.
- 원본 PNG와 저장소의 WebP 9쌍의 해상도·디코딩 RGBA 픽셀이 동일하다. 실제 휴대폰과 Safari의 프레임 성능은 이번 확인에 포함하지 않았다.

### 실제 확인한 원본

- 캐릭터 3명 × 기본·딴짓·친밀감 장면 = 서로 다른 PNG 9개. 원본은 약 1754–1756×895–896px다. 현재 합쳐진 화면에서 한 카메라가 차지하는 약 740×400px보다 확대 여유가 크다.
- 폰을 보는 사용자 PNG는 1542×1020px이고, 기본 사용자 소스는 1491×1055px의 네 카메라 합성 이미지다. 기본 사용자 화면은 그 원본의 오른쪽 아래 영역을 사용한다.
- 호감도 배지 `12:1660`, 이름표 `12:1667`, 말풍선 안의 텍스트가 사진과 별도 레이어임을 확인했다. 따라서 현재 `.session__photo--changed`의 말풍선 제거용 마스크와 중복된 이미지 속 UI를 없앨 수 있다.
- 확인한 캐릭터 원본은 정지 PNG다. 페이지에서 VIDEO fill은 발견되지 않았다. 세 포즈 간 전환의 품질은 높일 수 있으나 연속적인 눈 깜빡임·고개 움직임을 제공하는 영상 에셋은 아니다.

### 용량과 적용 순서

내려받은 비교용 소스 11개는 PNG 합계 **23.25MB**, 현재와 같은 무손실 옵션으로 변환하면 WebP 합계 **15.97MB**다. 현재 STEP 2·3의 합쳐진 WebP 두 개는 합계 **2.34MB**다. 모든 새 포즈를 한 번에 가져오면 전송량이 늘어난다.

교체 전 제안한 적용 순서:

1. 공통 기본 카메라와 설명에 필요한 반응·친밀감 포즈를 먼저 선별하고, STEP 1 입장 후·STEP 2·STEP 3에서 같은 기본 에셋을 공유한다.
2. `StudySessionPreview`의 사진을 슬롯별 이미지로 교체한다. 이름표·호감도·말풍선은 React UI로 구성하고, 사진에 인쇄된 UI를 가리던 마스크와 전체 화면 기준 크롭을 제거한다.
3. 기존 줌·선택·진행 시간·정지·모션 줄이기 동작을 이어 사용한다. STEP 2는 반응 포즈가 가장 잘 보이는 카메라에 시선을 맞추고, STEP 3은 호감도 변화와 포즈 전환 시점을 맞춘다.
4. 화면 진입 시 필요한 기본·다음 장면 이미지를 준비한다. 상태를 바꿀 때는 다음 이미지 디코딩 완료를 확인해 빈 프레임을 방지한다. 전체 포즈를 초기 화면에서 모두 준비하는 방식은 피한다.

이 비교에서는 Figma의 프레임 렌더·이미지 해시·원본 해상도·UI 분리와 임시 변환 용량을 확인했다. 교체 후 구현·브라우저 검증은 위 반영 내역에 기록한다.

## 재생·중단 규칙

- `StepDemo.tsx`는 시연 화면 전체를 하나의 네이티브 버튼으로 제공한다. 클릭·탭·Enter·Space로 다섯 장면을 순서대로 진행하며, 화면 오른쪽 아래의 별도 버튼은 재생·일시정지·다시 재생을 제공한다. 버튼을 중첩하지 않으며, 컨트롤의 실제 크기는 모바일에서도 44×44px이다.
- `useDemoPlayback.ts`는 화면에 40% 이상 들어오고 이미지 디코딩이 준비되면 자동 재생을 한 번 시작한다. 완료 후 자동 반복하지 않는다.
- 화면 밖 또는 숨겨진 탭에서는 남은 장면 시간을 저장하고, 복귀하면 남은 시간부터 이어진다. 사용자가 직접 멈췄다면 자동 재개하지 않는다.
- 수동 조작 시 예약된 자동 진행을 취소한다. 언마운트에서 타이머·관찰자·미디어 및 문서 이벤트를 정리한다.
- 모션 줄이기에서는 완성 장면을 정적으로 표시한다. 사용자가 다음 장면을 선택할 수 있고, 카메라 확대·이동, 커서 이동·클릭 표시·진행 바 이동은 사용하지 않는다. 필요한 상태 페이드만 100ms 유지한다. 포스터 하단 영역의 펼침도 제거한다.
- 포스터 확대 도중 닫기는 현재 사각형과 이미지 상태에서 되돌린다. 중간 리사이즈는 새 레이아웃으로 정착시킨다. 다른 페이지로 이동하면 애니메이션과 숨겨둔 원본 포스터를 정리한다.
- 닫기 완료 전에 원본 버튼의 가시성을 복구해 네이티브 다이얼로그의 포커스 복귀를 유지한다. 긴 설명으로 스크롤된 카드도 닫기 시작 위치를 다시 측정한다.
- WAAPI를 사용할 수 없거나 모션 줄이기일 때는 기존 모달 페이드 경로를 사용한다.

## 에셋과 표현의 한계

STEP 1은 Figma `1:177`의 원본 포스터·SVG·React UI를 재사용한다. STEP 2·3은 Figma `1:147`·`1:137`의 기존 WebP에서 카메라 영역을 CSS로 배치하고, 말풍선·시간·호감도·에피소드를 HTML/CSS로 렌더링한다. 카메라에 인쇄된 일부 작은 UI는 원본 이미지에 포함되어 있다. 추가 래스터 파일과 비디오 용량은 없다.

표정은 두 원본 프레임 사이의 전환이다. 실제 영상처럼 연속적으로 고개를 돌리거나 눈을 깜빡이는 동작까지 포함하지는 않는다. 그 수준의 움직임은 캐릭터 영상·애니메이션 원본이 있어야 한다. 호감도 값·새 대사·에피소드 제목은 기능을 설명하기 위한 예시다.

`intro-character.webp`의 실제 파일은 1024×1536px이다. 475×536px는 Figma의 크롭 표시 영역이며, 기존 상하 크롭은 유지했다. 데스크톱에서는 본문 밖의 이미지가 보이고, 좁은 휴대폰에서는 물리적인 화면 가장자리에서 잘린다.
