# UI 점검 기록 · 2026-10-10

이 여백 점검 이후 STEP 인터랙션 시연, 룸 포스터 확대·축소, 캐릭터와 페이드의 좌우 확장을 적용했다. 최신 동작은 [애니메이션 점검 기록](animation-review.md)에 정리했다. 아래 모션 문단은 그 이전 검토 상태의 기록이다.

랜딩의 전체 섹션, `/rooms`, `/survey`, `/preorder`, `/done`, 두 종류의 다이얼로그를 점검했다. 수치는 Figma 기준 폭 402px에서의 디자인 px이며, 작은 화면에서는 기존 `--u`에 따라 비례한다.

## 여백과 정렬

공통 기준은 본문 좌우 26px(`--page-inset`), 일반 카드 내부 16px(`--card-inset`)이다. 채워진 카드의 사방 여백과 화면 안의 정렬선을 함께 확인했다. 입력창이나 칩은 모양과 아이콘 공간에 맞는 별도 규칙을 사용한다.

## STEP 1 선명도

Figma 프레임 `1:176` 안의 인스턴스 `1:177`은 원본 `1:61`의 1480×852px 화면을 25%로 보여준다. 전체를 370×213px 이미지로 합치는 대신 `src/components/RoomSelectPreview.tsx`·`.css`로 구성했다.

텍스트와 UI 면은 HTML/CSS, 검색·체크·카메라·커서·캡슐은 원본 SVG, 8개 포스터는 원본 해상도 무손실 WebP를 사용한다. 기존 포스터 7개를 재사용하고 디자인이 다른 포스터 1개만 추가했다. 새 포스터는 1096×1436px이며 PNG 2,789,789 bytes → WebP 1,708,238 bytes, RGBA 픽셀과 ICC 프로파일 일치 확인. 합쳐진 STEP 1 이미지는 제거했다. 포스터 자체는 래스터이므로 원본 픽셀 수를 넘는 확대에는 한계가 있다.

브라우저에서 미리보기 370×213px, 포스터 좌표 `(82, 27)`부터 4열·2행, 각 65.5×87.5px 및 가로/세로 5px 간격을 확인했다. 기존 Figma export와 렌더링을 비교했고, DPR 3에서도 미리보기를 렌더링했다. 작은 UI의 글꼴은 프로젝트의 Pretendard를 사용한다. 미리보기의 검색·입장 표시는 설명용 장식으로 접근성 트리에서 제외했다.

## 검증

- `npm run build`: TypeScript 검사 및 프로덕션 빌드 통과.
- `npm run lint`, `git diff --check`: 통과.
- Chrome/Playwright로 5개 경로 × 5개 조건 = 25개 화면 상태 확인: 폭 320px, 402px, 1280px, 640px/DPR 2(1280px 화면의 200% 확대에 대응하는 뷰포트), 402px/RTL.
- 위 조건에서 가로 문서 넘침·깨진 이미지 없음. 주요 본문 좌우 여백과 일반 카드 사방 패딩 일치.
- 랜딩의 고민·STEP 1/2/3·안내·푸터를 320px·402px에서 각각 렌더링. 고민 카드와 안내문은 실제 글자 범위가 내용 영역 안에 있는지 추가 측정.
- 9개 포스터 열기, 제목/빈 설명 미표시, Esc 닫기와 버튼 포커스 복귀 확인. 일반 닫기, 등장 직후 닫기, 종료 이벤트 없는 경우 확인.
- 투표 → 수요조사 선택 → 사전예약 입력 → 필수 약관 동의 → 완료까지 확인. 선택한 긴 룸 제목이 사전예약·완료 카드에 유지됨.
- 필수·선택 약관을 320px·402px에서 렌더링. 모션 줄이기에서 룸 상세 등장 100ms와 즉시 종료 확인.
- 320×360px 화면에서 투표 및 약관 동의 버튼 접근 확인. 브라우저 내 테스트 데이터로 긴 설명과 가장 긴 룸 제목을 넣어 확인했으며, 이 문구는 저장소에 추가하지 않음.
- RTL에서는 본문 중앙 정렬과 넘침을 확인했다. 고정된 Figma 그림은 LTR 유지.

**Not verified:** 실제 기기의 Safari·Android 브라우저, 브라우저 메뉴의 실제 200% 줌, 번역된 문구·완전한 RTL 탐색 동작. 현재 앱은 한국어 문구를 사용하며, 200% 줌은 대응하는 CSS 뷰포트와 DPR로 검증했다.
