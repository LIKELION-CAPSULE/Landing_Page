# 반응형 화면 점검 · 2026-10-11

모바일의 기존 구도는 유지하고, 태블릿과 PC에서 본문·시연·예약 화면이 사용 가능한 폭에 맞춰 배치되도록 변경했다.

## 화면 폭에 따른 구성

| 화면 폭 | 구성 |
| --- | --- |
| 767px 이하 | 기존 402px 디자인과 `--u` 스케일을 유지한다. 문구, 포스터 순서·크롭, 버튼 위치, 모바일 시트 구도는 그대로다. |
| 768–1023px | Hero는 첫 문구와 맥북을 좌우로 배치하고 제목·간격·모델 폭을 창 크기에 맞춰 조정한다. 본문은 세로 흐름을 유지하며 STEP 시연과 입력 영역을 넓힌다. 고민·룸 갤러리의 그림만 해당 섹션 안에서 1.25배로 표시한다. 투표 포스터는 3열이며 약관 요약은 중앙 팝업이다. |
| 1024px 이상 | 최대 1120px 본문 안에서 첫 문구와 맥북을 좌우로 놓는다. STEP 설명과 시연은 번갈아 좌우로 배치한다. 고민 섹션은 문구와 캐릭터, 갤러리는 소개와 포스터를 나란히 보여준다. 투표는 5열, 예약 입력은 포스터와 폼, 완료 화면은 티켓과 안내·버튼, 설문은 소개와 입력 영역으로 나눈다. |

좌우 여백은 32–64px로 화면 폭에 맞춰 늘어난다. 폼과 문서의 읽기 편한 폭, 주요 버튼의 터치 영역, 키보드 포커스를 유지한다. PC에서도 내용이 길면 자연스럽게 줄바꿈되며 포스터 상세·약관 내부는 세로 스크롤이 가능하다.

## 구현

- `src/styles/responsive.css`를 기본·컴포넌트 스타일 뒤에 불러온다. 모바일 구도를 바꾸는 전역 크기 변경 없이 768px·1024px 미디어 쿼리로 적용한다.
- `--u`의 기본 값은 유지한다. 태블릿의 고민 그림과 갤러리, PC 갤러리만 자체 단위를 사용해 포스터 크롭과 반복 애니메이션의 이동 거리를 함께 조정한다.
- STEP 시연은 기존 `useDemoCanvas`가 표시 폭에 맞춰 1480px 원본 UI를 축소한다. 설명과 시연이 나란히 놓이는 경우 `useStepBackground`가 세로 그라데이션의 시작·정점·끝 순서를 유지한다. 모바일 배경 계산은 기존과 같다.
- 맥북 카메라는 기존 모델 영역의 실제 좌표로 계산한다. 90도 열림, 정면 자세, 타이핑·캡션 순서와 모션 줄이기를 유지한다. 768px 이상에서 모션 줄이기를 사용하면 본문 겹침을 없애 스크롤 안내가 다음 섹션에 가려지지 않게 한다.
- 룸 상세의 포스터 확대·축소는 기존 실제 사각형 측정을 사용한다. 화면 크기가 바뀌면 기존 훅이 진행 중인 전환을 정리하고 변경된 팝업 크기로 표시한다.

## 검증

- 320·390·402·430·767px에서 랜딩·투표·예약·완료·설문의 주요 요소 위치, 크기, 글자 크기, 배치 방식이 변경 전과 일치했다. 390px 랜딩 전체 캡처는 변경 전후 픽셀 차이가 없었다.
- 768·1024·1280·1440·1920px의 화면을 렌더링하고 검토했다.
- Chrome와 WebKit에서 390×844, 768×720, 1024×720, 1440×900의 총 8개 조합으로 랜딩 → 투표 → 예약 → 완료 → 설문 → 완료 흐름을 확인했다. 가로 스크롤과 잘리는 제목·본문이 없었고 런타임 오류도 없었다.
- 위 조합에서 룸 상세를 연 채 모바일·PC 폭 사이로 변경, Escape 닫기, 이메일 오류 포커스, 약관 보기·동의, 개인정보 전문 열기·닫기, 티켓 뒤집기, 설문 복수 선택·제출, 직접 진입한 빈 상태를 확인했다.
- 기본 모션 설정의 390×844, 1024×720, 1440×900에서 맥북의 0→90도 열림·프리뷰 표시·완료 자세 유지, STEP 직접 진행, 크기 변경 후 시연 캔버스의 표시 폭을 확인했다.
- 768×720, 1024×720, 1440×900의 모션 줄이기 설정에서 첫 화면과 다음 섹션이 겹치지 않음을 확인했다.
- `npm run build`와 `git diff --check`를 통과했다. 최종 빌드의 390·768·1440px 및 1024px의 글자 200% 확대 상태에서도 투표 → 예약 → 완료 → 설문 흐름과 제목 줄바꿈을 확인했다.

브라우저 검증은 독립된 임시 프로필과 로컬 개발 서버를 사용했다. Supabase 저장·집계와 분석 요청은 테스트 응답으로 대체해 실제 예약·투표 데이터를 만들지 않았다. 실제 기기의 Instagram 내장 브라우저와 라이브 DB 연동은 이번 검증 범위에 포함하지 않았다.

## PC 분할창의 Hero 보정

본문은 768px부터 반응형으로 넓어졌지만 Hero의 좌우 배치는 1024px부터 적용돼, 800~960px 분할창에서도 Hero만 402px 폭에 남아 있었다. Hero의 적용 기준을 768px로 맞추고 제목·보조 문구 크기와 열 사이 간격을 창 폭에 맞춰 조정했다. 맥북은 같은 원본 모델과 카메라 계산을 사용하며 표시 영역의 폭을 따른다.

- 960px 창에서 Hero 콘텐츠 폭은 402px → 약 883px, 모델 영역은 364px → 약 443px로 바뀐다.
- Chrome 16개와 WebKit 5개, 총 21개 조합으로 확인했다. 분할창 폭 768·800·900·960·1023px, 높이 600·720·820·1080px를 포함하며 제목·모델 겹침, 가로 스크롤, 런타임 오류가 없었다.
- 390·430·600·720·767px 모바일 구도와 1024·1440px 기존 PC 구도의 주요 요소 측정값이 변경 전과 같았다. 390·767·1024·1440px 캡처는 픽셀 차이가 없었다.
- 최종 빌드에서 768~1440px 사이로 12번 직접 창 크기를 바꿨다. 맥북이 절반 열린 상태의 진행률과 완전히 열린 90도 자세·프리뷰가 유지됐고, 역방향 스크롤도 동작했다.
- `npm run build`와 `git diff --check`를 통과했다.

## PC 말풍선 내부 경계와 사진 상단 보정

1024px 이상에서 디코 모각공 말풍선은 75px 높이지만 회색 장식이 모바일의 고정 50px 높이에 남아 있어 내부에 가로 경계가 보였다. 장식의 높이·폭을 말풍선 전체에 맞추고 같은 모서리 반경으로 잘라 경계를 없앴다.

사진 상단은 사진보다 위에서 시작하는 고정 회색 덮개를 숨기고, 사진 자체에 위쪽 100px가 투명하게 이어지는 마스크를 적용했다. Hero의 보라색 배경을 포함한 실제 뒤 배경이 드러나므로 사각형 띠가 생기지 않는다. 사진의 위치·크롭·크기는 유지하며 모바일·태블릿에는 기존 스타일을 적용한다.

- 최종 빌드에서 Chrome·WebKit의 390·767·960·1024·1440px, 총 10개 조합을 확인했다. PC 말풍선과 장식의 높이는 모두 75px이고, 사진 상단 덮개는 숨겨지고 마스크가 적용된다. 가로 스크롤과 런타임 오류는 없었다.
- 390·767·960px에서는 변경 전후 요소 측정값과 캡처가 동일했다. PC에서도 상단 덮개를 제외한 요소 위치·크기는 기존과 같았다.
- 기본 모션 설정의 PC에서 Hero와 본문이 겹치는 스크롤 구간을 렌더링해 사진 상단이 실제 배경과 이어지는 모습을 확인했다.
- `npm run build`와 `git diff --check`를 통과했다.

## PC 말풍선 배치 조정

회색 말풍선 세 개를 모두 오른쪽 사진 위로 옮겼다. 두 개는 사진 상단의 좌우에, 디코 모각공 말풍선은 얼굴 아래의 왼쪽에 둔다. 사진 폭·높이에 맞춰 위치를 계산하고 작은 기울기와 그림자를 적용해, 창이 좁아져도 사진 안에 머무르며 얼굴을 가리지 않는다. 밝은 사진에서도 읽을 수 있도록 짙은 회색 배경을 통일하고, 내부 경계를 만들던 모바일 흐림 장식은 PC에서 숨긴다.

캐릭터 대사는 사진 오른쪽 아래에 246×94px로 배치하고 18px 글자를 사용한다. 말풍선 꼬리는 같은 보라색으로 위쪽 캐릭터를 향하도록 배치했다. 왼쪽에는 제목만 남으므로 사진 옆 중간 높이에 문구를 정렬한다. 기존 모바일 SVG·배치는 그대로 두고 1024px 이상에서만 CSS로 적용한다. 이전 위치에 남던 흐림 장식은 PC에서 숨긴다.

- 최종 빌드에서 Chrome·WebKit의 390~1920px 총 10개 화면·모션 조합을 확인했다. 데스크톱에서는 말풍선 네 개가 사진 안에 들어가고 얼굴, 제목, 다음 질문을 가리지 않으며 서로 겹치지 않는다. 글자가 잘리거나 가로 스크롤과 런타임 오류가 발생하지 않았다.
- Chrome 1440px의 기본 스크롤 애니메이션에서도 말풍선이 정상적으로 나타났다.
- 390·960·1023px 캡처는 변경 전과 픽셀이 동일했다. 1023px 이하에서는 기존 말풍선 구도를 유지한다.
- 사진 상단 마스크를 유지하고 말풍선 내부 경계가 생기는 장식을 숨겼으며 `npm run build`, `git diff --check`를 통과했다.

## 이미지 드래그와 장식 선택 방지

모든 JSX 이미지에 `draggable={false}`를 적용한다. 이미지·고민 말풍선·캐릭터 대사·포스터 장식·클릭 시연에만 `user-select: none`과 WebKit 접두사를 사용하며, 서비스 설명·연락처·라이선스 표기·약관·입력칸에는 선택 제한을 적용하지 않는다. 페이지 전체의 마우스·터치·드래그 이벤트는 가로채지 않는다.

- Chrome와 WebKit의 모바일 390×844, 데스크톱 1440×900에서 실제 마우스 드래그로 이미지 드래그 및 말풍선 선택이 발생하지 않음을 확인했다.
- 같은 네 개 조합에서 서비스 설명·연락처 이메일·개인정보 전문·동의 안내가 선택되고, 이메일과 설문 입력칸의 전체 선택·편집이 유지됐다. 시연 클릭, 포스터 상세 보기, 투표·예약·설문 이동도 동작했다. 저장 요청에는 테스트 응답을 사용했다.
- MacBook 출처 링크와 CC BY 4.0 링크, 수정 표시, 배포되는 모델 출처 문서를 확인했다.
- 이미지·장식의 위치·크기·폰트 스타일은 변경하지 않았고 모바일·데스크톱 화면을 렌더링해 확인했다. 빌드·타입 검사와 `git diff --check`를 통과했다.
