# 기기 화면 크기·브라우저별 배치 검사

검사·수정일: 2026-10-11 (한국 시간)

랜딩, 룸 선택, 사전예약, 완료, 설문과 각 화면의 팝업을 검사했다. 기존 이메일 안내의 Safari 줄바꿈 문제 외에 **5개 유형의 배치 문제를 추가로 수정했다.** 수정 후 검사한 범위에서 가로 넘침·글자 잘림·검사 대상 간 겹침은 발견되지 않았다.

이 결과는 **로컬 브라우저 엔진과 화면 크기 시뮬레이션**이다. 실제 기종이나 운영 배포의 검증 결과는 아니다. 검사 수치와 상태별 결과는 [JSON 보고서](device-screen-review-report.json)에 기록했다.

## 발견한 문제와 수정

| 위치 | 발생 조건·증상 | 수정 |
| --- | --- | --- |
| 모바일 첫 화면 하단 | 320·402px에서 글자 200% 확대 시 소개 문구가 잘리거나 스크롤 안내·출처와 겹침 | 소개, 스크롤 안내, 출처가 내용 높이에 따라 공간을 차지하도록 변경 |
| 고민 섹션 | 확대 시 보조 문구가 좁은 화면 밖으로 나가거나 모바일·태블릿·PC에서 제목과 겹침 | 강제 한 줄 표시를 제거하고 제목과 보조 문구를 세로 흐름으로 배치. 그림은 별도 영역에 유지 |
| 스터디룸 갤러리 | PC 확대 시 설명과 고정 위치 버튼이 겹침. 좁은 화면에서는 커진 버튼이 섹션에 예약된 높이를 초과 | 버튼을 설명 다음에 배치하고 섹션 높이가 내용에 따라 늘어나도록 변경 |
| 선택 동의 팝업 | Chrome 계열의 320·402px, 글자 200% 확대에서 긴 이메일·제목 때문에 본문과 버튼이 오른쪽 화면 밖으로 밀림 | flex 자식의 최소 폭을 해제하고 긴 제목·이메일의 줄바꿈 허용 |

첫 화면의 제목·노트북, 고민 섹션의 그림·말풍선은 기존 구성을 유지한다. 설명이 길어지거나 글자가 커질 때 필요한 공간이 늘어난다.

기본 검사는 ‘모션 줄이기’ 조건으로 반복 가능한 배치를 측정했다. 320×568·402×874·844×390·768×1024·1024×600·1440×900에서는 **일반 모션**도 따로 검사했다. 타이핑 완료, 노트북 열린 상태, 고민 섹션 진입, 갤러리까지 확인했다. 402×874·1440×900의 일반 모션에서는 글자 200%도 검사했다.

402×874·768×1024·1440×900에서는 웹 글꼴 요청을 실패시켜 대체 글꼴로 랜딩·룸·예약·완료·설문을 확인했다. 402×874·1440×900에서는 글꼴을 3초 지연시켜 로딩 중과 로딩 후 배치를 비교했다. 추가 검사는 화면 배율(DPR) 2를 사용했고, 기본 검사는 DPR 1을 사용했다.

## 검사한 화면과 상태

- **랜딩:** 첫 화면, 고민 섹션, STEP 설명, 갤러리 버튼·출시 안내·푸터, 약관·개인정보 전문 및 팝업 내부 스크롤.
- **룸:** 9개 룸 상세, 긴 고양이 룸 이름, 투표 실패·재시도·성공 팝업.
- **사전예약:** 룸이 없는 직접 진입, 선택한 룸, 개인정보·선택 동의 요약 및 내부 스크롤, 개인정보 전문, 미입력·이메일 형식 오류, 긴 이메일 입력, 서버 오류·재시도.
- **완료:** 룸이 없는 직접 진입, 예약 티켓 앞면·뒷면, 중복 예약 안내, 설문 감사 상태.
- **설문:** 룸이 없는 직접 진입, 일반·작은 선택 버튼, 긴 자유 입력, 서버 오류·재시도·완료.
- **시연:** STEP 1·2·3의 총 20개 전환 상태를 320·402·1440px에서 각각 실행.

기본 38개 조합에서 **1,728회 화면·상태 검사**, 추가 모션·글꼴 조건에서 **112회**를 수행했다. 합계 **1,840회**이며, 이 중 루트 글자 200% 검사는 **244회**다. 동일 요소를 여러 상태에서 반복 측정한 값을 포함해 텍스트 요소 **37,090회**를 측정했다. 최종 측정에서 검사 대상 배치 오류, 처리되지 않은 페이지 JavaScript 예외, 검사 실행 오류는 모두 0건이었다.

텍스트의 계산된 크기, 문단 폭·줄 수·글줄 폭, 페이지 가로 스크롤, 화면 밖 글자, 숨김 영역에 잘린 글자, 제목·설명·버튼의 지정된 겹침 관계, 팝업 스크롤 영역을 측정했다. 대표 스크린샷도 확인했다. 숫자는 고유 화면이나 고유 글자 개수가 아니라 반복된 검사 횟수다.

## 이메일 안내의 후속 확인

페이지 본문에서 `text-wrap: pretty`가 적용된 곳은 기존 이메일 안내 문단 한 곳이었다. 해당 문단은 앞선 보정의 `wrap`·어절 유지·긴 문자열 줄바꿈 규칙을 유지한다. 나머지 `balance`는 가운데 정렬 캡션·버튼·강조 제목에 사용되는 설정이다.

19개 크기의 기본 글자와 5개 크기의 200% 글자, 총 24개 조건에서 두 엔진의 예약 안내 문단 폭과 줄 수가 일치했다. 글줄 폭의 최대 차이는 0.02px이었다. 이 수치는 같은 로컬 글꼴 환경의 결과이며 실기기의 글꼴 차이까지 보장하지 않는다.

## 검증 범위의 한계

실제 iPhone·Android·태블릿, 카카오톡 내장 브라우저, Samsung Internet, Firefox, 구형 브라우저 버전은 검사하지 않았다. 같은 폭이라도 실기기의 시스템 글꼴, 주소 표시줄, 노치·안전 영역, OS 글자 확대에 따라 차이가 날 수 있다. 390×400 검사는 창 높이를 줄인 조건이며 실제 키보드나 입력 시 자동 확대를 재현한 검사는 아니다.

200%는 문서 루트의 글자 크기를 늘린 검사다. 브라우저 전체 페이지 줌이나 OS 접근성 글자 크기 설정을 대체하지 않는다. 글꼴 실패 검사의 대체 글꼴은 로컬 macOS의 글꼴이다.

포스터에 인쇄된 글자와 고정 비율로 축소하는 시연·말풍선 내부 글자는 일반 본문 확대의 자동 판정 대상에서 제외했다. 시연 전환과 대표 그림은 별도 화면 검사로 확인했다. 자동 겹침 검사는 지정한 요소 관계와 안정된 애니메이션 상태를 대상으로 하며, 모든 픽셀과 모든 중간 프레임을 보장하는 검사는 아니다.

외부 API·집계·분석 요청은 테스트 응답으로 대체했다. 실제 예약·투표·설문 기록은 생성하지 않았다. 운영 서버 응답이나 운영 분석은 이번 배치 검사의 대상이 아니다.

`npm run build`, `npm run lint`, `git diff --check`를 통과했다. 기존 MacBook 컴포넌트 린트 경고 9개와 큰 번들 경고는 남아 있다. 변경 사항은 로컬 코드에 반영했으며 운영 배포는 하지 않았다.
