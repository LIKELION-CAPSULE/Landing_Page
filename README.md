# 캡슐 CAPSULE · 랜딩 페이지

> 같이 공부하고 싶은 **AI 공부 메이트**, 캡슐의 사전예약 랜딩 페이지입니다.

혼자 공부하면 30분도 버티기 힘들죠. 스터디위드미 영상은 나를 보고 반응하지 않고, 디스코드 모각공은 시간을 맞춰야 해요.
캡슐은 노트북 웹캠으로 나를 보고 반응하는 캐릭터와 함께 공부하는 서비스예요. 딴짓하면 캐릭터가 장난스럽게 말을 걸고, 공부한 시간만큼 캐릭터와 가까워져요.

이 저장소는 캡슐을 소개하고, 사용자가 **보고 싶은 스터디룸에 투표**한 뒤 **사전예약**까지 하도록 이끄는 페이지예요.
캡슐은 2026년 12월 기말고사 시즌에 웹으로 오픈합니다.

<br />

## 페이지 흐름

```
랜딩  →  스터디룸 투표  →  작품 상세  →  캐릭터 수요조사  →  사전예약 입력  →  입력 확인
 /         /rooms         (카드)          /survey          /preorder        /done
```

| 페이지 | 주소 | 설명 |
| --- | --- | --- |
| **랜딩** | `/` | 노트북 캠스터디 미리보기 → 혼자 공부할 때의 고민 → 캡슐의 사용 방법 3단계 → 스터디룸 갤러리 순서로 보여줘요. 각 STEP은 클릭과 화면 변화를 보여주는 시연이며 직접 눌러볼 수도 있어요. 하단 포스터는 Figma의 순서와 크롭을 기준으로 흘러내리고 일시정지할 수 있어요. |
| **스터디룸 투표** | `/rooms` | 9개 스터디룸 중 룸 1개를 골라요. 선택한 포스터에 체크 배지가 표시돼요. 사전예약 후 해당 룸 출시 시 무료 해금 혜택을 제공해요. 실제 집계 전에는 투표 수를 표시하지 않아요. |
| **작품 상세** | (투표 페이지 위 카드) | 누른 포스터가 그 자리에서 확대되고 상세 카드가 열려요. 포스터 하단 그라데이션이 확대와 함께 완성되고, 버튼 영역이 포스터에 붙은 채 아래로 펼쳐져요. 닫으면 포스터가 원래 자리로 돌아가요. 별도 제목은 표시하지 않고, 설명을 입력하면 포스터 아래에 보여줘요. **[이 스터디룸 투표하기]**로 투표해요. 룸은 하나만 고를 수 있어요. |
| **캐릭터 수요조사** | `/survey` | 관계·성격·세계관을 복수 선택하고 자유 입력(최대 500자)으로 답해요. 설문은 선택사항이며, **[다음: 사전예약]** 또는 **[건너뛰고 사전예약하기]**로 넘어가요. 건너뛴 상태와 응답한 상태를 구분하고, 작성한 초안은 돌아왔을 때 유지해요. |
| **사전예약 입력** | `/preorder` | 이메일·개인정보 동의는 필수, 나이대·공부 방식·마케팅 동의는 선택이에요. 룸·설문을 수정해도 입력이 유지돼요. 제출 시 오류와 수정 방법을 표시하고 첫 오류로 포커스를 옮겨요. 약관 **보기**는 요약 시트를 열어요. |
| **입력 확인** | `/done` | 확인한 이메일을 마스킹하고 선택한 포스터·혜택을 보여줘요. 입력 수정과 인스타그램 이동을 제공해요. 아직 서버 연결 전이므로 예약이 접수됐다고 표시하지 않아요. 직접 접속·새로고침·입력 변경 후 오래된 확인 화면 진입은 입력 안내를 보여줘요. |

페이지 사이는 앱처럼 옆으로 밀려 들어오는 전환으로 이어지고, 뒤로가기를 누르면 보던 위치로 돌아가요.
룸·설문·예약 입력은 같은 탭에서 페이지를 오가도 유지돼요. 브라우저 저장소나 서버에는 저장하지 않아 새로고침하면 초기화돼요.
세 단계 진행 표시와 경로 전환 후 포커스 이동을 제공해요. 화면 보완 사항과 백엔드에 전달할 계약 초안은 [사전예약 흐름 검토](docs/funnel-review.md)에 정리했어요.

## 기술 스택

- **React 19** + **TypeScript** + **Vite**
- 라우팅·애니메이션 라이브러리 없이 구현
  - 라우팅: `pushState` 기반 자체 훅 (`useRoute`)
  - 페이지 전환: View Transitions API (미지원 브라우저는 즉시 화면 전환)
  - 모달·시트: 네이티브 `<dialog>`, 룸 포스터는 Web Animations API로 확대·축소
  - STEP 시연: React 상태 + CSS 전환, 화면 안에 있을 때 한 번 자동 재생
- 린트: oxlint
- 폰트: Pretendard (CDN)

<br />

## 실행

```bash
npm install
npm run dev      # 개발 서버 (http://localhost:5173)
npm run build    # 타입 체크 + 프로덕션 빌드 (dist/)
npm run preview  # 빌드 결과 미리보기
npm run lint     # oxlint
```

현재 환경변수를 사용하는 코드가 없어 로컬 실행에 `.env` 파일은 필요하지 않아요.

## 폴더 구조

```
src/
├── pages/        페이지 단위 컴포넌트 (Landing, Rooms, Survey, Preorder, Done)
├── components/   랜딩 섹션(Hero, Problem, Steps, Rooms, Notice, Footer)과
│                 STEP 시연(StepDemo, RoomSelectPreview, StudySessionPreview),
│                 공용 UI(RoomSheet, TermsSheet, Checkbox, FunnelProgress, CheckIcon)
├── hooks/        useRoute(라우팅·전환), useReveal(스크롤 등장),
│                 useDemoPlayback(시연 재생), useRoomPosterTransition(포스터 확대),
│                 useAnimatedDialog(시트 닫힘 애니메이션), useHeroExitFallback
├── data/         페이지에 들어가는 내용 (아래 참고)
├── assets/       Figma 이미지 (무손실 WebP)와 SVG
└── styles.css    전역 스타일
```

디자인은 Figma의 iPhone 17 프레임(가로 402px)을 기준으로 해요. `styles.css`의 `--u` 값이 랜딩 에셋과 포스터 등의 크기를 320~402px 화면 폭에 맞춰 조정해요. 더 넓은 화면에서는 402px 폭으로 가운데에 놓여요. 입력 화면은 글자 크기 하한과 주요 동작의 44px 터치 영역을 유지하고, 글자가 커지면 문구와 선택 항목을 줄바꿈해요.
본문 좌우 여백은 `--page-inset`(26px), 일반 카드 내부 여백은 `--card-inset`(16px)을 기준으로 해요. 화면별 점검 결과와 의도적인 예외는 [UI 점검 기록](docs/ui-review.md)에 정리했어요.
고민 섹션의 캐릭터와 상하 페이드는 475px 폭을 본문 중앙에 맞춰 양쪽으로 같은 간격만큼 넘어 보여요. 402px 본문에서는 좌우 각각 36.5px예요. 가로 스크롤은 생기지 않고, 휴대폰에서는 화면 가장자리까지만 표시돼요.

## 애니메이션과 시연

- STEP 1: 커서 이동 → 룸 선택 → 입장 → 캠스터디 화면.
- STEP 2: 폰 확인 → 캐릭터 표정 변화 → 말 걸기 → 공부로 돌아가기.
- STEP 3: 공부 시간 증가 → 호감도 누적 → 새 에피소드 표시 → 에피소드 열기.

시연은 화면에 충분히 들어오면 STEP별로 6.3초·7초·8.5초 동안 한 번 재생해요. 선택할 포스터·입장 버튼, 폰 확인·캐릭터 반응, 공부 시간·호감도·에피소드 순서로 카메라가 확대·이동하며 중요한 부분을 보여줘요. 하단 캡션은 표시하지 않고, 장면 설명은 스크린리더에만 제공해요. 시연 화면을 클릭·탭하거나 키보드로 누르면 다섯 장면을 직접 진행할 수 있고, 화면 오른쪽 아래의 44px 버튼으로 일시정지·다시 재생할 수 있어요. 화면 밖이나 다른 탭에서는 시연 시간이 멈춰요. 모션 줄이기 설정에서는 확대·이동 없이 완성 장면을 정적으로 보여주고, 직접 다음 장면을 넘길 수 있어요.

현재 시연은 새 Figma의 캐릭터별 원본과 React/CSS로 구성해요. STEP 2는 폰을 보는 사용자와 류다희의 반응 포즈, STEP 3은 세 캐릭터의 친밀감 포즈로 전환해요. 이름표·호감도·말풍선은 이미지와 분리되어 확대할 때도 선명해요. 얼굴과 손동작을 보여주도록 말풍선·에피소드 알림 위치를 조정했어요. 원본은 정지 이미지이며 포즈 사이를 250ms로 전환해요. 호감도 숫자·새 대사·에피소드는 시연용 예시예요.
사진은 STEP 영역 근처에서 기본 이미지를 준비하고, 화면에 들어오면 다음 장면을 미리 불러와요. 다음 이미지가 준비되기 전에는 현재 장면을 유지하고 재생 시간을 잠시 멈춰요. 동일한 기본 에셋은 세 STEP이 공유해요.
검토 내용과 변경 전후는 [애니메이션 점검 기록](docs/animation-review.md)에 정리했어요.

## 디자인과 에셋 갱신

2026-10-10 기준 [Figma 디자인](https://www.figma.com/design/Xo30vZOPzJpzy2ggQKGVf2?node-id=0-1)의 랜딩·이후 섹션을 반영했어요.

| 화면 | Figma 노드 | 구현 |
| --- | --- | --- |
| 첫 화면 | `1:187` | `Hero.tsx`, `src/assets/hero/` |
| 랜딩 본문 | `1:100` | `Problem.tsx`, `Steps.tsx`, `Rooms.tsx` |
| STEP 1 미리보기 | 프레임 `1:176`, 인스턴스 `1:177`, 원본 `1:61` | `RoomSelectPreview.tsx`·`.css`: 텍스트와 UI를 React/CSS로 구성하고 SVG 아이콘·원본 포스터 사용 |
| STEP 2·3 시연과 STEP 1 입장 후 | `12:953`, `12:1030`, `12:1118` | `StudySessionPreview.tsx`: 캐릭터별 원본을 `src/assets/story/study-session/`에서 사용하고 시간·이름표·말풍선·호감도·에피소드를 UI로 구성 |
| 투표·상세 | `1:531`, `1:554` | `RoomsPage.tsx`, `RoomSheet.tsx` |
| 수요조사·사전예약·완료 | `1:370`, `1:451`, `1:426` | `SurveyPage.tsx`, `PreorderPage.tsx`, `DonePage.tsx` |

이미지와 SVG는 저장소에 포함된 로컬 파일로 사용해요. Figma MCP의 임시 URL은 앱에 넣지 않아요.
포스터와 화면 이미지는 원본 해상도·픽셀·투명도를 유지하는 무손실 WebP로 사용해요. 무손실 변환은 원본 이미지의 해상도를 바꾸지 않아요.
STEP 1은 370×213px로 합쳐진 이미지 대신, 1480×852px 원본 컴포넌트의 25% 인스턴스를 React로 구현했어요. 텍스트·UI·SVG 아이콘은 확대해도 선명하게 렌더링되고, 포스터는 약 1096×1440px의 원본 이미지를 사용해요. 미리보기 전체를 2배·3배 이미지로 다시 export할 필요는 없어요. 내부 검색창·작은 입장 표시는 설명용이고, 미리보기 전체를 누르면 시연이 진행돼요.
새 캠스터디 사진은 필요한 포즈 9개를 선별해 원본 해상도의 무손실 WebP로 사용해요. 합계는 약 13.23MB로 이전 합쳐진 이미지 두 개(2.34MB)보다 커요. 기본 사진 4개(6.06MB), 반응 2개(2.78MB), 친밀감 3개(4.39MB)를 장면에 맞춰 준비하며 처음부터 모든 포즈를 요청하지 않아요.
다음에 에셋을 갱신할 때는 해당 노드의 디자인 컨텍스트를 다시 읽고, 새 다운로드 URL과 저장 경로를 JSON 배열로 작성해요:

```json
[
  { "url": "Figma MCP에서 받은 다운로드 URL", "path": "src/assets/hero/study-room-preview.webp" }
]
```

```bash
brew install webp  # macOS: 에셋 갱신 시 사용하는 cwebp 설치
bash scripts/download-figma-assets.sh /tmp/figma-assets.json
```

이 스크립트는 `.webp` 경로의 이미지를 원본 해상도로 무손실 변환해 저장하고, SVG 등 다른 형식은 그대로 저장해요. 변환에는 `cwebp -lossless -q 75 -m 4 -exact -metadata icc`를 사용해요. 무손실 모드의 `-q`는 화질 대신 압축 효율에 영향을 주며, `-exact`는 완전히 투명한 픽셀의 색상도 보존해요. 기존 파일과 같으면 교체하지 않아요.
`cwebp`는 에셋 갱신할 때만 필요하고, 로컬 실행·빌드에는 필요하지 않아요.
