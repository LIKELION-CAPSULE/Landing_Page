# 캡슐 CAPSULE · 랜딩 페이지

> 같이 공부하고 싶은 **AI 공부 메이트**, 캡슐의 사전예약 랜딩 페이지입니다.

혼자 공부하면 30분도 버티기 힘들죠. 스터디위드미 영상은 나를 보고 반응하지 않고, 디스코드 모각공은 시간을 맞춰야 해요.
캡슐은 노트북 웹캠으로 나를 보고 반응하는 캐릭터와 함께 공부하는 서비스예요. 딴짓하면 캐릭터가 장난스럽게 말을 걸고, 공부한 시간만큼 캐릭터와 가까워져요.

이 저장소는 캡슐을 소개하고, 사용자가 **보고 싶은 스터디룸에 투표**한 뒤 **사전예약**까지 하도록 이끄는 페이지예요.
캡슐은 2026년 12월 기말고사 시즌에 웹으로 오픈합니다.

<br />

## 페이지 흐름

```
랜딩 → 스터디룸 투표·상세 → 투표 성공 안내 → 사전예약 입력 → 사전예약 완료
 /          /rooms         (/preorder 위)      /preorder        /done
                                                              ↓
                                               나만의 세계 만들어보기
                                                              ↓
                                             설문조사 /survey → 제출 성공 → /done
```

| 페이지 | 주소 | 설명 |
| --- | --- | --- |
| **랜딩** | `/` | 노트북 캠스터디 미리보기 → 혼자 공부할 때의 고민 → 캡슐의 사용 방법 3단계 → 스터디룸 갤러리 순서로 보여줘요. 각 STEP은 클릭과 화면 변화를 보여주는 시연이며 직접 눌러볼 수도 있어요. 하단 포스터는 Figma의 순서와 크롭을 기준으로 흘러내리고 일시정지할 수 있어요. |
| **스터디룸 투표** | `/rooms` | 같은 모서리 값(9 디자인 px)의 포스터 9개 중 룸 1개를 골라요. 선택한 포스터에 체크 배지가 표시돼요. 투표는 Supabase에 저장하고, `landing_vote_total()`이 반환한 고유 방문자 수를 표시해요. 첫 집계 요청은 로딩·실패를 구분하고, 돌아올 때는 마지막으로 확인한 숫자를 유지해요. |
| **작품 상세** | (투표 페이지 위 카드) | 누른 포스터가 그 자리에서 확대되고 상세 카드가 열려요. 포스터 하단 그라데이션이 확대와 함께 완성되고, 버튼 영역이 포스터에 붙은 채 아래로 펼쳐져요. 닫으면 포스터가 원래 자리로 돌아가요. 별도 제목은 표시하지 않고, 설명을 입력하면 포스터 아래에 보여줘요. **[이 스터디룸 투표하기]**로 저장이 성공하면 같은 오버레이가 투표 성공 안내와 **[좋아요]** 하나로 바뀌고, 뒤 화면은 `/preorder`로 전환돼요. 좋아요를 누르면 예약을 입력할 수 있어요. 저장 실패는 상세 카드에서 재시도해요. |
| **사전예약 입력** | `/preorder` | 선택한 룸, 이메일, 약관 동의를 보여줘요. 이메일·개인정보 동의는 필수, 마케팅 동의는 선택이에요. **룸 변경은 예약할 룸만 바꾸며 처음 저장한 투표는 유지해요.** 변경 후 같은 오버레이에 **변경 성공!**, **아쉽게도 스터디룸 투표 변경은 불가능해요 :(**, **[괜찮아요]**를 표시해요. 룸을 변경하거나 뒤로 돌아가도 입력이 유지돼요. 제출 시 오류와 수정 방법을 표시하고 첫 오류로 포커스를 옮겨요. 약관 **보기**는 요약 시트를 열어요. |
| **사전예약 완료** | `/done` | Supabase 저장 성공 후 완료 안내와 마스킹 이메일·선택한 포스터·혜택을 보여줘요. 중복 이메일은 별도 안내로 기존 예약이 변경되지 않았음을 알려요. 저장 실패나 환경변수 누락 시 완료 화면으로 이동하지 않아요. 하단에는 **나만의 세계 만들어보기**, 인스타그램, 처음으로 돌아가기 세 동작을 제공해요. 직접 접속·새로고침하면 완료 정보를 확인할 수 없다는 안내를 표시하며, 접수된 예약은 DB에 유지돼요. |
| **설문조사** | `/survey` | 예약 완료 후 **[나만의 세계 만들어보기]**로 들어와 관계·성격·세계관을 복수 선택하고 자유 입력(최대 500자)으로 답해요. **[의견 보내기]**로 별도 저장한 뒤 완료 화면에 돌아가 감사 문구를 표시해요. 제출하지 않고 돌아갈 수 있고, 초안은 유지돼요. 저장 실패 시 답변을 유지하고 재시도해요. |

페이지 사이는 앱처럼 옆으로 밀려 들어오는 전환으로 이어지고, 뒤로가기를 누르면 보던 위치로 돌아가요. 투표·룸 변경 성공 시에는 오버레이를 유지한 채 배경만 즉시 바꿔요.

사전예약 화면은 카드 배경 없이 포스터를 크게 보여줘요. `선택한 룸` 라벨은 생략하고 무료 해금 안내는 배경 없이 포스터 상단에 겹쳐 표시해 부드럽게 반복해서 깜빡여요. 룸 이름 아래의 회색 **스터디룸 변경할래요!** 밑줄 링크로 예약할 룸을 바꾸며, 구분선은 이메일 입력 위에 있어요. 모션 줄이기 설정에서는 혜택 문구를 고정 표시해요.
입력 초안과 완료 화면 정보는 같은 탭에서 페이지를 오가도 유지되지만 새로고침하면 초기화돼요. 제출된 투표·사전예약은 Supabase에 저장돼요. 설문은 예약 완료 후 `landing_survey`에 별도로 저장하며, 예약 정보는 수정하지 않아요. 제출하지 않은 답변은 전송하지 않아요. 이메일·응답은 브라우저 저장소에 보관하지 않고, 집계를 위한 익명 방문자 ID만 보관해요.
상단에는 번호·문구 대신 가로 진행 게이지를 표시해요. 룸 선택 33% → 사전예약 입력 67% → 저장 완료 100%로 채워지며, 뒤로가기와 같은 줄에 놓아요. 설문에서는 게이지를 표시하지 않아요. 경로 전환 후 포커스 이동도 제공해요. 저장 규격은 [프론트 연동 스키마](docs/frontend-schema.md), 설정은 [데이터 수집 안내](docs/data-collection.md), 화면 변경 기록은 [사전예약 흐름 검토](docs/funnel-review.md)에 정리했어요.

랜딩 하단 **이용 약관**, **개인정보처리방침**은 각각 전문 오버레이를 열어요. 모바일에서는 전체 화면으로 표시하고, 문서 내부를 스크롤할 수 있어요. 사전예약 하단의 개인정보처리방침도 같은 전문을 열어요. 문구 원본은 `src/data/legal/terms.md`, `src/data/legal/privacy.md`에 있으며, 사전예약 **보기** 요약은 `src/data/preorder.ts`에서 관리해요. 개인정보처리방침의 `[대괄호]`에 남은 위탁 서비스·국외 이전 정보는 실제 운영 내용에 맞춰 채워야 해요.

## 기술 스택

- **React 19** + **TypeScript** + **Vite**
- 라우팅·애니메이션 라이브러리 없이 구현
  - 라우팅: `pushState` 기반 자체 훅 (`useRoute`)
  - 페이지 전환: View Transitions API (미지원 브라우저는 즉시 화면 전환)
  - 모달·시트: 네이티브 `<dialog>`, 룸 포스터는 Web Animations API로 확대·축소
  - STEP 시연: React 상태 + CSS 전환, 화면 안에 있을 때 한 번 자동 재생
- 린트: oxlint
- 폰트: Pretendard 기반 로컬 서브셋 (`Capsule UI`), 필요한 추가 글자는 로컬 원본에서 로드

## 실행

```bash
npm install
npm run dev      # 개발 서버 (http://localhost:5173)
npm run build    # 타입 체크 + 프로덕션 빌드 (dist/)
npm run preview  # 빌드 결과 미리보기
npm run lint     # oxlint
```

화면 실행·빌드에는 `.env`가 필요하지 않아요. 실제 투표·사전예약·설문 저장에는 `.env.local`에 `VITE_SUPABASE_URL`, `VITE_SUPABASE_ANON_KEY`를 설정해야 해요. 후자는 publishable key 또는 기존 anon key를 받아요. Mixpanel 분석은 `VITE_MIXPANEL_TOKEN`이 있을 때만 켜져요. 키가 없으면 로컬 화면은 열리지만 예약을 완료했다고 표시하지 않아요. 변수 목록은 `.env.example`을 참고하세요.

## 폴더 구조

```
src/
├── pages/        페이지 단위 컴포넌트 (Landing, Rooms, Survey, Preorder, Done)
├── components/   랜딩 섹션(Hero, Problem, Steps, Rooms, Notice, Footer)과
│                 STEP 시연(StepDemo, RoomSelectPreview, StudySessionPreview),
│                 공용 UI(RoomSheet, TermsSheet, Checkbox, FunnelProgress, CheckIcon)
├── hooks/        useRoute(라우팅·전환), useReveal(스크롤 등장),
│                 useDemoPlayback(시연 재생), useRoomPosterTransition(포스터 확대),
│                 useAnimatedDialog(시트 닫힘 애니메이션), useHeroExitFallback,
│                 useStepBackground(STEP 위치에 맞춘 html 배경)
├── data/         페이지에 들어가는 내용 (아래 참고)
├── lib/          Supabase REST 저장·집계, Mixpanel 분석
├── assets/       Figma 원본·SVG, optimized/의 배포용 WebP, fonts/의 로컬 폰트
└── styles.css    전역 스타일
```

디자인은 Figma의 iPhone 17 프레임(가로 402px)을 기준으로 해요. `styles.css`의 `--u` 값이 랜딩 에셋과 포스터 등의 크기를 320~402px 화면 폭에 맞춰 조정해요. 더 넓은 화면에서는 402px 폭으로 가운데에 놓여요. 입력 화면은 글자 크기 하한과 주요 동작의 44px 터치 영역을 유지하고, 글자가 커지면 문구와 선택 항목을 줄바꿈해요.
본문 좌우 여백은 `--page-inset`(26px), 일반 카드 내부 여백은 `--card-inset`(16px)을 기준으로 해요. 화면별 점검 결과와 의도적인 예외는 [UI 점검 기록](docs/ui-review.md)에 정리했어요.
고민 섹션의 캐릭터와 상하 페이드는 475px 폭을 본문 중앙에 맞춰 양쪽으로 같은 간격만큼 넘어 보여요. 402px 본문에서는 좌우 각각 36.5px예요. 가로 스크롤은 생기지 않고, 휴대폰에서는 화면 가장자리까지만 표시돼요.
STEP의 배경은 페이지 최하층인 `html`에 그려요. 검은색은 각 STEP의 글자 영역 중앙에 집중되고, 상하좌우로 부드럽게 옅어져요. 영상 아래에는 넓고 옅은 흰색 그라데이션을 놓아요. 화면 크기나 글꼴이 달라지면 실제 요소 위치에 맞춰 다시 계산하고, 랜딩을 벗어나면 배경을 정리해요.

## 애니메이션과 시연

- STEP 1: 새 포스터 구성에서 룸 선택 → 보라색 선택 테두리 → 입장 → 호감도 0 → 공부 시간과 호감도 증가. 해시태그는 표시하지 않아요.
- STEP 2: 폰 확인 → 캐릭터 표정 변화 → 말 걸기 → 공부로 돌아가기.
- STEP 3: 공부 시간과 호감도 증가 → 강채린·한수아·류다희가 차례로 말 걸기 → 호감도 100 → 다음 에피소드 열기.

시연은 화면에 충분히 들어오면 STEP별로 12.3초·7초·15.5초 동안 한 번 재생해요. STEP 1은 선택할 포스터·입장 버튼을 확대한 뒤, 전체 스터디룸에서 시간과 세 호감도를 함께 보여줘요. STEP 2는 폰 확인과 캐릭터 반응, STEP 3은 공부 시간·각 캐릭터의 대사·에피소드로 카메라가 이동해요. STEP 3의 각 대사는 해당 장면이 시작된 뒤 호감도가 오르는 것을 먼저 보여주고 나타나요. 커서는 STEP 1의 포스터 선택 구간에만 나타나요. 하단 캡션은 표시하지 않고, 장면 설명은 스크린리더에만 제공해요. 시연 화면을 클릭·탭하거나 키보드로 누르면 STEP별 8개·5개·7개 장면을 직접 진행할 수 있고, 화면 오른쪽 아래의 44px 버튼으로 일시정지·다시 재생할 수 있어요. 화면 밖이나 다른 탭에서는 장면 진행과 시간·호감도 숫자가 함께 멈춰요. 모션 줄이기 설정에서는 확대·이동 없이 완성 장면을 정적으로 보여주고, 직접 다음 장면을 넘길 수 있어요.

현재 시연은 Figma의 ‘스텝별화면’ 섹션을 기준으로 캐릭터별 원본과 React/CSS로 구성해요. STEP 2는 폰을 보는 사용자와 세 캐릭터의 반응 포즈로 전환하고, 별도의 ‘잠깐 폰 확인 중’ 문구는 표시하지 않아요. STEP 3은 각 캐릭터의 친밀감 포즈와 Figma 대사를 차례로 보여줘요. 이름표·호감도·말풍선은 이미지와 분리되어 확대할 때도 선명해요. 원본은 정지 이미지이며 포즈 사이를 250ms로 전환해요. 시간은 기능을 보여주기 위해 빠르게 흐르고, 호감도 값과 다음 에피소드 내용은 시연용 예시예요.
사진은 STEP 영역 근처에서 기본 이미지를 준비하고, 화면에 들어오면 다음 장면을 미리 불러와요. 다음 이미지가 준비되기 전에는 현재 장면을 유지하고 재생 시간을 잠시 멈춰요. 동일한 기본 에셋은 세 STEP이 공유해요. 룸 선택 포스터와 랜딩 갤러리도 해당 영역 300px 전부터 요청하고, `/rooms`의 포스터는 지연 로딩해요.
STEP 안은 1480px 기준의 큰 UI를 전체 축소해 표시해요. Android WebView에서 작은 CSS 글자만 최소 크기로 커지는 영향을 줄이며, 이 그림 영역에만 글자 자동 보정을 제한해요. 페이지 확대와 일반 본문·입력 화면의 글자 확대는 유지해요.
검토 내용과 변경 전후는 [애니메이션 점검 기록](docs/animation-review.md)에 정리했어요.

2026-10-10 기준 [Figma 디자인](https://www.figma.com/design/Xo30vZOPzJpzy2ggQKGVf2?node-id=0-1)의 랜딩·이후 섹션을 반영했어요.

이미지와 SVG는 저장소에 포함된 로컬 파일로 사용해요. Figma MCP의 임시 URL은 앱에 넣지 않아요.
`src/assets/`에는 원본 해상도의 무손실 WebP를 보존하고, 앱에서는 `src/assets/optimized/`의 배포용 복사본을 사용해요. 배포용 사진은 고품질 손실 WebP로 압축하고, 포스터 해상도는 유지해요. 캠 사진은 대부분 1280px 폭, 첫 화면 스크린샷은 1536px 폭으로 조정해요. 사용자 카메라의 합성 원본 크롭과 고민 섹션 캐릭터의 해상도는 유지해요. 현재 빌드의 WebP 27개는 합계 약 39.09MB에서 4.16MB로 줄었어요.
STEP 1은 370×213px로 합쳐진 이미지 대신, 1480×852px 원본 컴포넌트의 25% 인스턴스를 React로 구현했어요. 텍스트·UI·SVG 아이콘은 확대해도 선명하게 렌더링되고, 포스터는 약 1096×1440px의 원본 이미지를 사용해요. 미리보기 전체를 2배·3배 이미지로 다시 export할 필요는 없어요. 내부 검색창·작은 입장 표시는 설명용이고, 미리보기 전체를 누르면 시연이 진행돼요.
캠스터디 사진은 기본·반응·친밀감 포즈를 장면에 맞춰 준비하며 처음부터 모든 포즈를 요청하지 않아요. 이름표·호감도·대사는 이미지 압축과 별개로 React UI에서 렌더링해요.
다음에 에셋을 갱신할 때는 해당 노드의 디자인 컨텍스트를 다시 읽고, 새 다운로드 URL과 저장 경로를 JSON 배열로 작성해요:

```json
[
  { "url": "Figma MCP에서 받은 다운로드 URL", "path": "src/assets/hero/study-room-preview.webp" }
]
```

```bash
brew install webp  # macOS: 에셋 갱신 시 사용하는 cwebp 설치
bash scripts/download-figma-assets.sh /tmp/figma-assets.json
npm run assets:optimize # 원본에서 배포용 복사본 재생성
```

이 스크립트는 `.webp` 경로의 이미지를 원본 해상도로 무손실 변환해 저장하고, SVG 등 다른 형식은 그대로 저장해요. 변환에는 `cwebp -lossless -q 75 -m 4 -exact -metadata icc`를 사용해요. 무손실 모드의 `-q`는 화질 대신 압축 효율에 영향을 주며, `-exact`는 완전히 투명한 픽셀의 색상도 보존해요. 기존 파일과 같으면 교체하지 않아요.
`cwebp`는 에셋 갱신할 때만 필요하고, 로컬 실행·빌드에는 필요하지 않아요.

새로 추가한 **조선시대 야간 학습** 포스터의 원본은 `src/assets/rooms/joseon.jpeg`에 보관하고, 배포에는 `src/assets/optimized/rooms/joseon.webp`를 사용해요. `/rooms`와 랜딩 갤러리 가운데 열이 같은 파일을 공유해요. `assets:optimize` 실행 시 이 JPEG에서 배포용 WebP를 다시 만들어요.

폰트는 [Pretendard 공식 배포](https://github.com/orioncactus/pretendard)의 v1.3.9 원본을 로컬에 보관해요. 기본 화면은 약 118KB의 서브셋 하나를 미리 불러오고, 약관 전문에 필요한 추가 글자는 오버레이를 열 때 약 12KB의 별도 서브셋으로 불러와요. 두 서브셋에 포함되지 않은 입력 글자는 약 2.06MB의 원본 폰트를 필요할 때 불러와요. `font-display: swap`을 적용하고 외부 CDN 요청을 제거했어요. 폰트 파일도 Vite가 해시가 포함된 경로로 배포해요. 서브셋은 OFL의 예약 이름 조건에 맞춰 `Capsule UI`로 이름을 바꿨으며, 글꼴 모양은 Pretendard와 같아요. 라이선스는 `public/fonts/LICENSE.txt`와 원본 디렉터리에 포함해요.
문구를 크게 변경한 뒤 서브셋을 다시 만들려면 Python 가상환경에서 `pip install 'fonttools[woff]'`를 설치하고 `python scripts/subset-font.py`를 실행해요. 이 도구는 일반 실행·빌드에 필요하지 않아요.
